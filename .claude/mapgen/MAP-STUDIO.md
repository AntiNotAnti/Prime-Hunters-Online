# Map Studio and custom-map projects

Map Studio is a desktop authoring surface in the existing single GLFW window. Open **Map Studio** on the front screen or use `-mapstudio`. Android and dedicated servers share validation, compilation, assets, packages, and transfer; they do not host the editor viewport.

## Ownership and source compatibility

`MapDocument` owns a detached `MapProject`. Common edits retain deltas for affected objects; bulk replacements retain bounded snapshots. Background operations receive separate snapshots. Geometry compiles into `BuiltFace`, then the established `BuiltMap -> MapPacker` pipeline writes ordinary MPH model, animation, collision, entity, and node files. MapGen has no Avalonia dependency. The viewport caches individual native objects and imported architecture separately; selection and camera movement do not rebuild geometry. It does not pack collision or regenerate navigation during a drag.

Missing `FormatVersion` means v1. Discovery never upgrades or rewrites old recipes. New templates use v2, a persistent `MapId`, runtime `Name`, optional `InGameName`, author, version and description. **Upgrade project** assigns identity in memory; Save persists it. Names are limited to 40 ASCII letters, digits, spaces, underscores and hyphens, with filesystem device names rejected. Built-in room keys cannot be replaced.

The v1 material/brush/spawn/pad/item fields stay compatible. V2 adds Box, Wedge, Prism and closed ConvexBrush geometry with a `kind` discriminator, normalized quaternion transforms, UV defaults and optional face overrides, editor labels/layers/visibility/locking, team spawns, mode capabilities, audio and assets. Initial entity classes share `MapEntityDefinition`; the existing typed lists remain the serialized compatibility contract.

## Authoring workflow

1. Create Blank Arena, Simple Box Arena or Team Arena, or import a BSP/PK3 through the Q3 wizard. PK3 import runs a read-only preflight first: it lists contained BSPs, projected MPH dimensions, surfaces/patches/brushes, starts, pickups, texture coverage and every archive searched. The selected PK3 is searched first, explicit dependencies next and sibling PK3s last. Common Q3 shader-script indirection is resolved before direct-image fallback. Missing art gets an obvious deterministic checker texture; geometry is never hidden merely because its source image is absent.
2. Select objects in the hierarchy or viewport. Shift selects multiple objects and dragging empty viewport space box-selects. RMB orbits, MMB pans, wheel zooms, WASD/QE moves, and F frames the selection. Ctrl+A/C/V select/copy/paste; G/R/T choose move/rotate/scale; H, Shift+H and Alt+H hide, isolate and reveal authored geometry. Top/front/side views provide orthographic editing.
3. Use Move, Rotate or Scale, axis handles and numeric properties. Snapping settings expose position, angle and scale steps plus local/world transforms. Defaults are 0.25 units, 15 degrees and 0.25 scale. Layers can be shown, hidden, locked, unlocked or assigned to the current selection.
4. The inspector edits environment, geometry, entities, UVs, named materials, textures and music. Game materials show their source, name, dimensions, format and a cached thumbnail. Custom textures are baked to a single-texture `.tex` pack. Arrange can save a selection as a reusable prefab or insert a saved prefab as one undoable edit.
5. Validate for full geometry/source/budget checks. Basic source validation runs after 500 ms of inactivity. Problems select their associated object. The Navigation overlay builds the bot graph on demand, colors connected regions and shows directed routes. Explicit traversal links connect nearby walkable nodes; they do not create physical teleporters or platforms.
6. Save writes a JSON project atomically. Save As from a package materializes only referenced assets. Build writes runtime files and registers the map for Play without restarting. Replacement invalidates the room model/collision caches while retaining old GL lists until scene cleanup. Build .ppmap captures the viewport preview and produces a portable package. Play from here uses an isolated room snapshot and one camera-position spawn; return to the launcher to resume editing. Run map test runs the existing 22-second, eight-player bot/gameplay/render audit in a child process and reports its actual exit status.

Undo/redo retains up to 500 commands and 256 MiB of estimated history. Dirty state compares current and saved document identities in O(1); undo to the saved identity clears it. A drag is one command, and continuous property changes can coalesce without crossing a save boundary. Autosaves occur after three seconds of inactivity in `maps/.autosave`, with source context stored beside the recovery JSON. Opening an existing project offers Restore/Discard/Inspect; Library > Recover unsaved also finds never-saved documents. Autosave never overwrites the source. Delete and unsaved-discard actions require confirmation.

The library refreshes its own catalog and shows previews, metadata, source type, diagnostics and build status. Library thumbnails and material previews are cached for the screen lifetime and invalidated by their source identity/timestamp instead of being decoded on every pane refresh. Package and source precedence is identity-aware. Background jobs lock editing and publish UI results on the UI thread. Cancelling a caller stops its wait immediately; shared build work continues for other callers and the cache. Audit cancellation terminates only its child process.

Q3 imports are transactional. Conversion happens in a sibling staging directory and the finished project is moved into place only after the source, texture bake and project write succeed; cancellation or failure removes staging so retrying the same runtime name is safe. The desktop shell accepts `.pk3`, `.bsp`, `.json` and `.ppmap` files dropped on the native GLFW window while Map Studio is visible. Existing imports expose **Rebake Q3 textures** and **Reimport Q3 source**. Reimport replaces source architecture/art while retaining Project Prime-authored metadata, entities, assets and hybrid geometry.

## Validation and reproducible output

`MapBuildScheduler.Shared` runs runtime build, validation, navigation and packaging through one queue (two workers, 32 unique jobs). Editor, CLI, package installation and client/server room preparation use those entry points. Identical jobs share one task; different consumers share private compiled geometry in an eight-entry, 128 MiB estimated cache. UI results expose immutable geometry and detached navigation graphs. Runtime binaries persist under the user-local `ProjectPrime/map-cache/<fingerprint>` directory. File leases serialize publication and installation across processes; integrity hashes and dependency checks reject corrupt or stale output. Native validation remains available without cartridge files. Missing PK3-derived texture packs are prepared in the bounded queue before the final fingerprint is fixed; source changes during preparation still reject the job.

`MapDependencyAnalyzer` supplies content fingerprints and the portable asset set used by packaging, package reference checks and Save As. Base-room content affects runtime fingerprints but is never packaged. Source directories are part of in-memory compiler-cache identity because compiled imports retain path resolvers; persistent binary cache identity depends on content.

`MapOutputSet` owns all five filenames. A missing output, damaged output, changed source/import/texture/asset, schema or compiler setting makes the build stale. `map.build.json` records SHA-256 fingerprints and output hashes. Every output is prepared before publication; the sidecar is written last, so interruption causes regeneration on the next launch.

Diagnostics carry stable `FP-MAP-*` codes, severity and optional object ID. Validators check geometry transforms/ranges/topology, materials/assets, spawn placement/headroom, multiplayer pickups, jump-pad settings, modes, imported dependencies and collision budgets. Runtime limits produce warnings at 70%/90% and errors at 100%. `-mapinspect` also generates navigation and reports node/edge budgets.

Closed convex brushes must enclose a nonzero volume; a flattened tetrahedron is invalid even when every edge belongs to two faces. Relative import and texture paths resolve beside the project before the working-directory and library fallbacks, so an unrelated same-named file cannot change the map being compiled or packaged.

```text
ProjectPrime -mapvalidate "TEST ARENA" -mapdir maps
ProjectPrime -mapinspect "TEST PADS" -mapdir maps
ProjectPrime -mapbuild "TEST ARENA" -mapdir maps -out build-map
ProjectPrime -mapbundle all -mapdir maps
ProjectPrime -mapstudio
```

Validate/inspect do not require launcher setup for native maps or imports with their own texture packs. Runtime builds using borrowed materials require the user's extracted game files. Validation cannot verify a borrowed material index against unavailable cartridge data; packing checks it before replacing any output.

## Packages and multiplayer

V2 `.ppmap` is a ZIP containing `manifest.json` and `project.json`; import, texture, audio and preview directories are optional. Native maps need no BSP. Legacy one-recipe packages still load. Imported packages carry a trimmed `import/level.bsp` and baked `textures/map.tex`. Packaging copies only declared map assets, never extracted game audio or borrowed cartridge textures.

Entries are sorted, timestamps fixed, and the canonical content hash includes each path, length and bytes except the manifest. A separate archive SHA-256 can verify the exact package file. The reader bounds compressed size to 128 MiB, expanded content to 256 MiB, individual entries to 64 MiB, projects to 8 MiB and entries to 2048. It rejects traversal, rooted/device paths, duplicates, unsupported types, inconsistent identity, missing assets and hash mismatches. Files are read from the archive rather than extracted over the library.

Device-name checks apply before the first dot in each path component on every platform, including multi-extension names such as `CON.backup.tex`.

The package reader/installer are shared infrastructure for future map distribution, but this port does **not** enable PR #53's old protocol-8 network-transfer layer. Project Prime's multiplayer protocol has evolved since that PR, so automatic server-to-client custom-map delivery must be integrated separately against the current networking stack rather than reviving the old packet/version changes. Local Map Studio build/package/install flows remain fully verified and atomic.

## Verification and current limits

`dotnet run --project tools/map-editor-check -c Release` exercises document identities, bounded delta history, viewport invalidation, snapshot isolation, shared compilation, cancellation, queue bounds, independent scheduler publication, package roundtrips, cache integrity, editor clipboard/layers, PK3 dependency discovery, failed-import cleanup, hybrid material offsets and prefab roundtrips using synthetic data without proprietary assets. `--benchmark` compares dirty/transform work on 1,000 native objects. `-mapstudioshot DIR` captures 1440x900 and 960x600 editor layouts. The separate `-mapcheck ROOM` CLI audits collision geometry and coverage; it deliberately analyzes raw geometry, including shapes the publishing compiler rejects.

The viewport uses the game's world shader, materials and display lists for shaded authoring meshes. Each native object and the imported architecture retain independent GPU meshes. Selection and camera changes only alter render parameters; moving an object uploads that object alone. Imported render and collision meshes are separate cached inputs. Back-face culling matches runtime packing. Lightweight entities, selection handles and navigation remain Avalonia overlays, drawn above the GPU world. A common camera/layout contract drives projection, ray picking, framebuffer placement and explicit preview capture. Headless screenshots and renderer failure use the CPU fallback. Closing the editor releases its private resources without rebinding foreground scene state.

`-mapviewportcheck DIR [-mapproject FILE]` exercises real GL rendering at three window sizes, framebuffer pointer selection, preview capture, overlay order, mesh reuse and cleanup. Linux CI runs it under Xvfb and uploads the images. The optional project adds an imported-map draw/raster microbenchmark; these are component times, not whole-editor frame times. The viewport retains authoring colors rather than runtime textured lighting.

Imported BSP architecture remains read-only, but an imported project is now hybrid: native Box, Wedge, Prism, ConvexBrush and legacy brush geometry may be layered over the BSP. Imported texture-pack materials occupy the first runtime material range and authored Project Prime materials are appended after it, so the two sources cannot alias each other's indices. The viewport keeps the immutable imported mesh and authored object meshes in separate caches. Prefabs preserve their selected objects and required material/texture assets, assign fresh object IDs on insertion and insert as one history operation. Convex brushes still support numeric transforms and serialized vertices/faces; full vertex/edge modeling, CSG and scripting remain outside this editor. Spawn weighting and per-mode entity filtering are not yet runtime features. Mode capabilities reject unsupported objective modes instead of producing nonfunctional matches. Custom audio uses the existing player with volume/loop/pause support; decode failure falls back to room music.

Large maps still use the proven single-room-part output. A partitioning follow-up must split render groups into spatial cells while preserving collision plane/index ownership, bot graph connectivity, RoomMetadata node names, remote-player NodeRef mapping and portal visibility. Gate it with the existing all-spawn render sweep, node agreement probes and DUST2 regression before enabling it. The current compiler budgets provide the guardrails; no alternate runtime map engine is introduced.
